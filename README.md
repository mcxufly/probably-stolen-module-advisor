# 模块搭配助手 / Module Advisor 0.3.0

为《深空当铺：可能是偷的》提供机器和模块搭配预览。使用游戏原生模组加载器和自定义 UI，无 Harmony 补丁。

## 使用

1. 把安装包内的 `ModuleAdvisor` 文件夹解压到游戏的 `Mods/`，使目录形如 `Mods/ModuleAdvisor/manifest.xml`。
2. 在游戏模组菜单启用“模块搭配助手 / Module Advisor”，重启游戏并载入存档。
3. 按 **F6** 打开窗口。可在游戏选项 → 按键绑定中修改“打开模块搭配助手”；不需要开发者模式或 `dev.txt`。
4. 在“机器”和“空闲模块”页勾选本次参与搭配的物品。首次打开默认全选，后续刷新保留仍存在的选择；新获得物品须勾选或点全选。
5. 选择均衡、性能优先、节能优先或品质优先；再选择即时／长期稳健／长期期望／短期冲刺，输入1–100次预测范围（默认30次稳健）。点击“生成方案”，进入“搭配结果”页。
6. 照“摆放图”手动安装：`X`为不可用格，`·`为空位，`E1…`为已有物品，`N1…`为推荐新增物品；同编号的所有格属于同一件物品，颜色辅助区分，图下有名称图例。悬停格子可查看说明。行列从 **1** 起算，同时保留坐标、旋转和翻转文本。已有模块保持原位，非矩形形状和孔洞会按真实占格绘制。
7. 物品移动、出售、机器运行状态变化、安装模块后重新生成；新获得物品先刷新。关闭窗口或切换存档后重新打开即可使用。

窗口使用原生滚动列表、勾选框、下拉和标签页，支持中文/英文；鼠标悬停物品显示基础属性、所在容器、原版功能与词条说明。同名物品通过实例编号区分。F9 Special 也提供入口，但普通使用只需 F6。

## 搭配规则

- 扫描店内递归物品，只选玩家及其父容器均归玩家所有的机器和模块。
- 通过原生 `module` 面板获取模块槽。已装在任何已识别模块槽中的模块、已锁定模块、无法从原容器移出的模块不参与空闲分配。
- 依据实际实例的模块类型、形状、剩余空间、旋转、翻转、原版接受条件及工作锁检查候选位置。每个模块最多推荐一次，推荐之间不会争用同一格，也不会覆盖已有模块。
- 对当前构建核对过的 11 种机器，按属性实际用途估算收益。例如炉子不计性能加成，报警器和解序器不计品质加成。优先属性权重为其他属性的 3 倍；均衡三者同权；负属性会扣分，无正分时保留空位。
- 单次候选位置检查规模上限为 80000，超过时提示缩小机器/模块选择范围。
- 评分先以实例基础数值重算**整槽**，包含支持节点、接收器、负反馈、顶部/左侧词条及其对已有物品的影响。邻接按真实占格的上下左右接触，不算对角；同一邻居不按接触格数重复计数。双词条按原版顺序和整数截断处理。
- 节点正式参与自动分配。搜索允许单独零收益的节点或模块与其他物品组成正收益组合，不再先按单件基础分排除。比较当前布局→候选布局的有效收益；最后迭代移除不再贡献收益的新增物品，避免饱和后无意义堆叠。
- 使用有界动态 beam search、空间采样和坐标改良：每模块最多采样64个位置、总评分回调最多30000次，单次候选位置检查上限80000。启发式不保证全局最优，不同机器/用途之间的偏好权重也不代表最高经济收益。
- 化学升级和改变生产功能的模块仍另外列出“功能参考”，不自动决定改变生产路线。参考列表逐件检查当前物品栏，不预留计划空间，参考之间可能冲突；化学机器已有4个模块时不列第五级。
- 结果显示初装整槽P/E/Q、每件新增属性、有效结果和上限提示，另以累计曲线显示学习增长、退化及随机过压毁坏。尚不预测未来健康变化、原料补给或经济售价。
- 第三方机器只有采用原生 `module` 面板才能被发现；未核对数值消费者的机器只显示兼容参考。其他模组自定义的接受/状态委托仍由游戏调用，其行为由该模组负责。

当前数值配置支持：种植机、植物 DNA 操作机、打印机、解序器、警报器、熔炉、集水器、净水器、蒸发器、幻象投影器、议价机器。兼容性判断仍以运行时原生槽规则为准。

## 属性上限与场景边界

并非所有属性都在100%封顶。本版采用当前游戏的实际消费规则：

|机器/结果|计算与上限|
|---|---|
|每周期电耗|最低1，按基础电耗、倍率与整数截断计算；达到最低值后不再奖励无效节能|
|报警器|按实际拦盗骰子计算，性能P49即100%，极负P仍保留原版最低1%|
|净水器|品质Q15/25/50/75/100/200依次跨纯度阶梯，Q200达到100%；性能按水质≥98%的参考污垢倍率估算，不假装预测任意液量/污垢的实际净化量|
|蒸发器|回收率夹在0–100%；挥发预算按原版浮点与舍入计算，无虚构性能上限|
|集水器|品质Q150为最高纯水档，产水量自身无统一上限；共享空气和瓶容量另行限制|
|DNA操作机|有种子时按当前有效复杂度与品质计算5%–100%成功率，无种子只估品质加成；已开工操作保留原先成功率快照|
|熔炉|有足量原料时按本次消耗顺序、鼓风模块和助熔剂预测最终六档纯度，最高完美；缺料只比较品质档位偏移|
|种植机|有种子时比较原版取整后的参考收获基数；芦苇不消费该基数，品质收益为0；健康、作物回调、固定功能增产、副产物和物品尺寸价值不包含在评分内|
|打印机|品质收益依配方而异，枪架/部分枪械无通用上限，近战武器状态另有档位；本版保守比较品质加成，不虚构统一上限|
|议价机|最终议价率依顾客、报价、派系与事件夹到0–100%；只比较机器提供的机会加成，不假定固定品质就必定成功|
|幻象投影器/解序器|按当前消费规则比较吸引力/速度；无通用上限的不强行封顶|

当前原版支持机器都只有一个模块槽。第三方替换同ID机器逻辑、非标准占格值或额外模块槽不属于已验证数值支持范围。图示超过24×24时回退坐标文本。当前完整网格窗口仍需游戏内确认布局和缩放。

## 长期预测（0.3.0）

- **默认未来30次、稳健、不自动补换。** 可输入1–100次，非法输入恢复上次有效值。
- 次数指原版`OnMachineActioned`/词条触发次数，**不是天数、成品数量或每次完成配方**。种植机每有效生长周期、DNA/打印机每有效加工周期都可能触发；报警器即使没有电也会触发。当前原版议价机不触发这些效果，预测不令其模块老化。
- 学习读取当前基础值与存档内已有上限，不重新初始化；达到上限停止，缺省0上限的负属性也可向0恢复。退化仅减少正属性，负属性保持不变。
- 每步重算整槽节点、接收器、负反馈和属性上限。大多数机器按本步变化前的效果评分；报警器/解序器按原版顺序使用旧节能、新性能。DNA的成功率仍是配方启动快照，逐tick综合分不是实际成品成功数。
- 过压用每次独立10%毁坏的固定随机路径模拟；30次后的单件存活解析值约4.24%。对同一物理物品跨方案采用相同寿命抽样，不调用或改变游戏随机数。
- 毁坏对象替换为零属性、无词条的L形废件；在可接收时按原版翻转/旋转/首空位插入，容量或锁定不允许时不再留在该舱。不补换或免费购买新模块。
- DNA触发时模块舱锁定；种植机/打印机完成周期的锁状态依进度不同，本版按工作中锁定保守处理并明确标记阶段近似。未完整模拟配方完成时刻、健康、供电/供水中断或第三方规则。
- 稳健直接比较**累计新增收益P10**，期望比较均值，冲刺比较前`min(5,次数)`次均值，无隐藏风险系数。均值/P10是样本估计，不是保证；至少一件毁坏概率单独解析显示。
- 即时布局先用0.2.0搜索，再以16条固定路径做有限长期位置改良；结果64条路径复核，与即时方案和不加模块方案比较，不保留复核后更差的方案。有限搜索不保证最佳长期组合。
- 蓝线为当前方案平均累计新增偏好收益，橙线为即时推荐方案；横轴触发次数，纵轴偏好分，**不是信用点**。同时显示P10、风险、持续交叉点和新增长期模块的期末平均基础属性/存活概率。图示及属性明细仍表示初装状态，不是期末残骸摆放。
- 预测固定当前配方/原料背景；不把一份原料当成真实无限补给，也不统计购买、拆装和替换费用。因此曲线是条件效用对比，不是产量账本或经济最优保证。

升级旧版时退出游戏，用0.3.0安装包替换旧模组内容，再启动游戏；不需要重置存档。

## 存档与卸载

助手只预览，不生成物品、不转移、不拆装、不消耗模块，不添加存档中的自定义机器/模块，也不保存分配方案。关闭并禁用模组、重启即可卸载，无需清理存档。快捷键配置由原生 ModConfig 保存；勾选状态只保留在当前游戏会话，切换存档会重置。

## 开发与打包

需要 .NET SDK 8+ 和本机游戏程序集。构建和验证只写项目目录：

```bash
bash build.sh
# 非默认游戏路径：
bash build.sh -p:GameDir="/path/to/Probably Stolen"
# 核心算法：
dotnet run --project tests/Planner.Tests.csproj -c Release
# 真实接口、扫描（先构建打包）：
dotnet run --project verification/GameApiChecks.csproj -c Release -- 0.46D
python3 tools/check_localization.py
```

`GameDir`/`ManagedDir` 可覆盖。打包脚本在 `dist/ModuleAdvisor/` 生成仅含自己的 DLL、清单、本地化和玩家说明的干净内容，并生成安装 ZIP。游戏 DLL、反编译输出、工具和开发测试不会随包分发。
